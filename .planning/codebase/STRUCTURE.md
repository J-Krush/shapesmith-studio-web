## Directory Purposes

**`public/`:**
- Purpose: CRA static asset folder served at the root; injected into the build verbatim.
- Contains: `index.html` (with hidden Netlify form declaration so Netlify Forms can detect the schema at deploy time), favicon, web app manifest.
- Key files: `public/index.html`, `public/manifest.json`.

**`src/pages/`:**
- Purpose: One component per route. Pages are layout-thin and primarily compose feature components inside the right Context providers.
- Contains: `.jsx` route components.
- Key files: `src/pages/Home.jsx`, `src/pages/ProjectSingle.jsx`, `src/pages/Contact.jsx`, `src/pages/Materials.jsx`.

**`src/components/`:**
- Purpose: Feature-scoped UI building blocks.
- Contains: One subfolder per feature surface (`home/`, `projects/`, `about/`, `contact/`), plus `shared/` for app-wide chrome and `reusable/` for primitives.
- Key files: `src/components/shared/AppHeader.jsx`, `src/components/projects/ProjectsGrid.jsx`, `src/components/contact/ContactForm.jsx`.

**`src/context/`:**
- Purpose: React Context providers that fetch Sanity data with `useEffect` + GROQ and expose state to a subtree.
- Contains: `AboutMeContext.jsx`, `ProjectsContext.jsx`, `SingleProjectContext.jsx`.
- Key files: `src/context/ProjectsContext.jsx` (referenced by both Home and ProjectSingle pages).

**`src/utilities/`:**
- Purpose: Cross-cutting non-UI code.
- Contains: Sanity client singleton, image URL helpers (legacy Google Drive fallback path).
- Key files: `src/utilities/sanityClient.jsx`.

**`src/hooks/`:**
- Purpose: Custom hooks.
- Contains: `useScrollToTop` (renders the floating up-arrow), `useThemeSwitcher` (currently unused — the app forces dark mode in `App.js`).

**`src/data/`:**
- Purpose: Pre-Sanity static seed data. Only `capabilitiesTitle` from `src/data/projects.js` is still consumed by the app.
- Contains: JS modules with exported arrays/strings.
- Note: Treat the rest of this directory as **legacy** — `materials.js`, `aboutMeData.js`, `singleProjectData.js`, and `images.js` are no longer imported.

**`src/assets/`:**
- Purpose: Build-time imported images (logos, brand marks, hero image).
- Contains: PNG/JPG. Imported directly into JSX via ES module imports (e.g. `import logoDark from '../../assets/logo-flower-of-life-dark.png'`).

**`src/fonts/`:**
- Purpose: Self-hosted font files (GeneralSans family + Proxima Nova).
- Contains: `.eot`, `.ttf`, `.woff`, `.woff2` variants.

**`src/css/`:**
- Purpose: Hand-rolled global CSS plus the optional standalone Tailwind compile target.
- Contains: `App.css` (imported by `App.js`), `tailwind.css` (source for the `build:css` script), `main.css` (generated artifact).

**`src/materials/`:**
- Purpose: Holds `MaterialSingle.jsx`. Sits at `src/materials/`, **not** under `src/components/`. This is a structural inconsistency — it should arguably live at `src/components/materials/MaterialSingle.jsx`.

## Key File Locations

**Entry Points:**
- `public/index.html`: HTML shell, mount target, Netlify hidden form.
- `src/index.js`: React bootstrap.
- `src/App.js`: Router definition.

**Configuration:**
- `package.json`: scripts (`start`, `build`, `test`, `build:css`), dependencies, ESLint config (extends CRA's `react-app`), browserslist.
- `tailwind.config.js`: dark mode `class`, custom color palette (`primary-light`, `accent`, etc.), container padding scale.
- `postcss.config.js`: Tailwind + autoprefixer pipeline.
- `.gitignore`: ignores `node_modules`, `build`, `coverage`, `src/images`, env files.

**Core Logic:**
- `src/utilities/sanityClient.jsx`: Sanity `@sanity/client` singleton with hardcoded `projectId` and `dataset`.
- `src/context/ProjectsContext.jsx`: Primary CMS data source for the `/styles` and `/styles/:capability` routes.
- `src/data/projects.js`: Source of `capabilitiesTitle` constant used to build URLs.

**Testing:**
- `src/App.test.js`: CRA stock test (currently failing — looks for the string "learn react" which isn't on the page).
- `src/setupTests.js`: Jest-DOM matcher import.

## Naming Conventions

**Files:**
- React components: `PascalCase.jsx` (e.g. `AppHeader.jsx`, `ProjectsGrid.jsx`).
- Hooks: `camelCase.jsx` starting with `use` (e.g. `useScrollToTop.jsx`, `useThemeSwitcher.jsx`).
- Plain JS modules / data: `camelCase.js` (e.g. `aboutMeData.js`, `singleProjectData.js`, `helpers.jsx`, `sanityClient.jsx`).
- Context providers: `<Domain>Context.jsx` (e.g. `ProjectsContext.jsx`).
- Inconsistencies present: utilities use `.jsx` even though they have no JSX (`sanityClient.jsx`, `helpers.jsx`); `contact-form.js` uses kebab-case while every other component file uses PascalCase.

**Directories:**
- Feature folders under `src/components/` are lowercase (`home/`, `projects/`, `about/`, `contact/`, `reusable/`, `shared/`).
- `src/context/`, `src/data/`, `src/hooks/`, `src/pages/`, `src/utilities/`, `src/assets/`, `src/fonts/`, `src/css/` all lowercase singular/plural based on convention.

**Components:**
- Default exports for the main component (`export default ComponentName`).
- Named exports for Context objects and providers (`export const ProjectsContext = ...`, `export const ProjectsProvider = ...`).

**Routes:**
- Route paths are kebab-case lowercase: `/styles`, `/materials`, `/about`, `/contact`.
- The `:capability` segment is a slug (kebab-case) coming from Sanity's `slug` field.

## Where to Add New Code

**New route (page):**
- Page component: `src/pages/<Name>.jsx`. Follow the existing page pattern: thin layout wrapper, mount any required Context provider, compose feature components.
- Register route: add `<Route path="/<segment>" element={<Name />} />` in `src/App.js` and add a lazy import alongside the other `lazy()` calls (`src/App.js:14-18`).
- Nav link: add a `<Link>` in both the small-screen and large-screen menu sections of `src/components/shared/AppHeader.jsx`.

**New feature UI:**
- Pick the matching feature folder in `src/components/` (e.g. home/, about/, projects/) — or create a new lowercase folder if it's a new domain.
- File: `src/components/<feature>/<ComponentName>.jsx`.
- Reuse `src/components/reusable/FormInput.jsx`, `Button.jsx`, `SocialLinks.jsx` for primitives.

**New Sanity-backed content type:**
- Decide between Context vs. inline fetch:
  - Cross-page or shared by siblings → add a provider in `src/context/<Name>Context.jsx` mirroring `ProjectsContext.jsx`.
  - Single page only → fetch inline with `useEffect` + `useState` like `src/pages/Materials.jsx`.
- All fetches go through `import sanityClient from '../utilities/sanityClient'` (or `'../../utilities/sanityClient'` from deeper paths).
- GROQ queries should follow the existing shape: project the fields you need and dereference image assets with `asset->{ _id, url }`.

**New custom hook:**
- File: `src/hooks/use<Name>.jsx`. Default-export the hook. Follow the `useScrollToTop` style.

**New utility / helper:**
- File: `src/utilities/<name>.jsx` (note: existing files use `.jsx` extension even for non-JSX — match that for consistency, or migrate the whole folder to `.js`).

**New static asset:**
- Build-time imported image: drop into `src/assets/` and `import` it from a component.
- Public asset (referenced by URL string): drop into `public/`.
- Sanity-managed image: upload in Sanity Studio, dereference via `asset->url` in the GROQ query.

**New test:**
- Co-locate next to the component as `<Name>.test.js` (CRA Jest convention). Note: `src/App.test.js` is the only test currently and is broken — fix or delete it before adding more.

**`build/`:**
- Purpose: CRA production build output.
- Generated: Yes (by `npm run build`).
- Committed: No (`.gitignore` line 13).

**`node_modules/`:**
- Purpose: pnpm-installed dependencies.
- Generated: Yes.
- Committed: No.

**`src/images/`:**
- Purpose: Referenced by `src/.gitignore` rule `# local images / /src/images`. The folder does not currently exist on disk; legacy `singleProjectData.js` references `../images/` which would break if that file were imported.
- Generated: No.
- Committed: No.

**`coverage/`:**
- Purpose: Jest coverage output.
- Generated: Yes.
- Committed: No.

**`src/data/`:**
- Purpose: Was the source of truth before Sanity migration. Treat as legacy except for `capabilitiesTitle` in `src/data/projects.js`.
- Generated: No.
- Committed: Yes.
