# Phase 3 — UI Design Contract

> Visual and interaction contract for the Auto-Pricing Quote Tool (`/quote`). Generated by gsd-ui-researcher, verified by gsd-ui-checker. Covers the full phase (Plan 03-01 stub through 03-NN submission), so visual decisions are locked once for the whole tool — not re-negotiated plan-by-plan.

## Design System

| Property | Value |
|----------|-------|
| Tool | none — manual Tailwind matching existing project conventions |
| Preset | not applicable |
| Component library | none — extend existing patterns in `src/components/{reusable,services,shared}/` |
| Icon library | `react-icons/fi` (Feather subset; only icon set in repo) |
| Font | `GeneralSans-Variable` family (custom) + `font-display` for hero/section heads |

**Why no shadcn:** PROJECT.md §Constraints locks the stack to CRA + React 18 + JS — no new component library introductions allowed (visual identity is "targeted spruce, same fonts, same palette"). Phase 2 established the manual Tailwind + custom-component pattern across 9 service surfaces; Phase 3 extends that, not replaces it. Registry safety gate: not applicable.

**Source of truth for visual identity (locked in Phases 1+2, do NOT re-derive):**
- `tailwind.config.js` — `accent #348bd8`, `accent-highlight #3c6eb1`, `primary-dark #291c30`, `secondary-dark #102D44`, `ternary-dark #1E3851`, `secondary-section-dark #594a60`, `ternary-section-dark #94989c`, `primary-light #F7F8FC`, `secondary-light #FFFFFF`, `ternary-light #f6f7f8`, `secondary-section-light #d1d1d1ff`. Token name `ternary` (not `tertiary`) — preserve the typo per CONVENTIONS.md.
- `src/css/App.css` — `font-general-{regular,medium,semibold,bold,extralight,…}`, `font-display`. Use existing classes; do NOT add new font weights or families.
- `dark:` prefix is the active styling pattern (Phase 1 left dark-pair classes in component files; only `-light` color tokens are used as the dark-mode targets per FOUND-03 D-08). New components MUST follow the same `text-primary-dark dark:text-primary-light` pairing convention.
- `framer-motion` `AnimatePresence` already wraps `<App>` — reuse `motion.*` for tab transitions and reveal animations; no new motion library.
- `@tailwindcss/forms` plugin styles file inputs and selects automatically.

## Spacing Scale

Declared values (all multiples of 4, matching Tailwind's default 4px step):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px (`p-1`, `gap-1`) | Inline-icon gaps within buttons/badges |
| sm | 8px (`p-2`, `gap-2`) | Tight cluster spacing (chip rows, label-input pairs) |
| md | 16px (`p-4`, `gap-4`, `mb-4`) | Default element spacing — form rows, card body padding |
| lg | 24px (`p-6`, `gap-6`, `mb-6`) | Section internal padding, card outer padding |
| xl | 32px (`p-8`, `gap-8`, `mb-8`) | Major form-block separation (file pane → readouts pane) |
| 2xl | 48px (`py-12`, `mb-12`) | Major section breaks (intro → tool, tool → submit) |
| 3xl | 64px (`py-16`, `sm:py-24`) | Page-level vertical rhythm (matches Phase 2 `py-12 sm:py-24` section pattern in `MaterialsSection`/`FAQ`/`WontMake`) |

**Exceptions:**
- Dropzone min-height: `min-h-[12rem]` (192px) on mobile, `sm:min-h-[14rem]` (224px) on desktop — sized for comfortable drop target, not on the 4px scale (driven by visual weight not rhythm).
- Tab strip vertical padding: `py-3` (12px) — sits within the `py-12 sm:py-24` page section, kept compact so tabs feel like a control not a hero element.

**Container:** Reuse the Phase 2 `container mx-auto` pattern with the existing custom `container.padding` from `tailwind.config.js` (`DEFAULT 1rem / sm 2rem / lg 5rem / xl 6rem / 2xl 8rem`). Do NOT introduce a new container scheme.

## Typography

All sizes/weights below are TAILWIND CLASSES THAT ALREADY EXIST IN THE CODEBASE — no new font weights, no new font families. Existing Phase 2 typography rhythm is inherited verbatim.

| Role | Tailwind class | Computed | Weight class | Line-height | Usage |
|------|---------------|----------|--------------|-------------|-------|
| Body | `text-base` | 16px | `font-general-regular` (400) | `leading-normal` (1.5) | Default paragraph copy, dropzone instruction text, geometry-readout values |
| Label | `text-lg` | 18px | `font-general-medium` (500) | `leading-snug` (1.375) | Form field labels (matches `FormInput.jsx` precedent) |
| Subhead | `text-2xl sm:text-3xl` | 24/30px | `font-display` `font-bold` | `leading-tight` (1.25) | Tab-content section heads ("Upload your file", "Geometry summary"), price-range header — matches `MaterialsSection` / `FAQ` `<h2>` rhythm |
| Display | `text-3xl sm:text-4xl` | 30/36px | `font-display` `font-black` | `leading-tight` (1.25) | `/quote` page H1 ("Get an instant ballpark") — matches `AppBanner` H1 cadence |

**Rules:**
- Exactly **2 weights** in active use: regular (`font-general-regular`, 400) for body and `font-general-medium` (500) for labels/CTAs. Headings use `font-display` `font-bold`/`font-black` — those are heading-only and don't break the 2-weight body rule (they're the same headings rule Phase 2 uses).
- Disclaimers, helper text, and unit-warning notes use `text-sm` (14px) `font-general-regular` `text-ternary-dark dark:text-ternary-light` — this is a fifth size used ONLY for non-primary microcopy (matches `ContactForm.jsx:230` `text-sm text-ternary-dark dark:text-ternary-light` pattern). Do not promote `text-sm` to a primary role.
- Numeric readouts (volume, bbox, path length, file size) use `font-general-medium` `text-base` for the value and `text-sm font-general-regular text-ternary-dark dark:text-ternary-light` for the label — definition-list rhythm, not table grid.
- Italic is **not** used in this surface. The disclaimer ("estimate, final price subject to confirmation") is muted via `text-ternary-dark dark:text-ternary-light` color, NOT via italic — italic risks reading as decorative on a legal-posture line.

4. Focus ring on form inputs/buttons: `focus:ring-1 focus:ring-accent` — matches `ContactForm.jsx:220` precedent.
5. Inline links inside body copy: `hover:text-accent` (no default accent color on link text — accent only appears on hover, matching `MaterialsSection.jsx:34`/`FAQ.jsx:40` "Contact us" pattern).
6. **Accent NOT used for:**

**Destructive actions:** Phase 3 introduces no destructive actions per se. Adjacent affordances:
- "Replace file" / "Clear file" inside the dropzone after a successful drop — NOT destructive (replaces local state only, no server effect). Style: `text-ternary-light hover:text-primary-light` text button, no confirmation dialog. Copy: "Replace file" (preferred) or "Remove" (if planner picks).
- "Start over" / "Clear form" if the planner adds it for QTE-10 localStorage-restore UX (Plan 03-02+) — also NOT destructive (local state only). Inline text button, same muted color.
- Submit failures: error banner uses `text-red-400` `role="alert"`, no confirmation dialog, no destructive styling.

### Tab UI

- **Tabs are visual, NOT URL-deep-linked.** The URL is `/quote` regardless of which tab is active. A `?service=laser|print` query string ONLY pre-fills the initial active tab — it is NOT written back when the user clicks the other tab. (Rationale: the URL would feel jumpy mid-task; a single `/quote` SEO surface is the D-04 commit; matches the contact form's pre-fill-only pattern in `ContactForm.jsx:35-52`.)
- **Initial tab selection cascade** (matches `ContactForm.jsx` D-24):
  1. `?service=laser` or `?service=print` → matching tab active.
  2. `?service=laser-cutting`, `?service=3d-printing`, `?service=styles` → mapped via `SERVICES.find(s => s.urlSegment === q || s.key === q)`.
  3. `document.referrer` includes `/styles` → laser tab; includes `/3d-printing` → 3D tab.
  4. Otherwise → 3D tab default (3D printing is the *new* surface; defaulting to it nudges visitors toward the shinier offering on cold-load).
- **Visual treatment:**
  - Active tab: `text-primary-light font-general-medium border-b-2 border-accent pb-2` (matches `AppHeader.jsx:49` active-route pattern verbatim).
  - Inactive tab: `text-ternary-section-dark hover:text-primary-light` (no border).
  - Tab container: horizontal `flex gap-8 mb-12 border-b border-secondary-section-dark` so the active tab's bottom border visually merges with the strip rule.
- **Keyboard navigation** (WAI-ARIA tabs pattern):
  - `role="tablist"` on the container, `role="tab"` on each button, `role="tabpanel"` on the content.
  - `aria-selected={isActive}`, `aria-controls={panelId}`, `tabIndex={isActive ? 0 : -1}` on tabs.
  - `Left`/`Right` arrow keys cycle between tabs; `Home`/`End` jump to first/last; `Enter`/`Space` activates.
  - Tab content updates focus to the panel (or the dropzone inside it) when the tab changes.
- **Motion:** `framer-motion` `AnimatePresence` with `mode="wait"` wrapping the active panel; `motion.div initial={{ opacity: 0, y: 8 }} animate={{ opacity: 1, y: 0 }} exit={{ opacity: 0, y: -8 }} transition={{ duration: 0.2 }}`. Subtle crossfade with 8px slide — no slide-the-whole-strip, no flashy reveal. Matches `AppBanner.jsx:33` `ease: 'easeInOut', duration: 0.9` cadence (shorter here because tab-switching should feel snappy).

### File upload dropzone

- **Container:** `<div role="region" aria-label="File upload">` wrapping a label-as-button pattern so click-to-pick and drag-and-drop both work without nesting interactive elements.
- **States** (all four states must be visually distinct):
  - **Idle:** `border-2 border-dashed border-secondary-section-dark bg-ternary-dark/40 rounded-xl p-12 text-center cursor-pointer`. Icon (`FiUploadCloud` from `react-icons/fi`) at 48px, muted `text-ternary-section-dark`, above the dropzone copy.
  - **Hover (mouse over, file not yet being dragged):** `border-ternary-light` (lighter dashed border), no fill change.
  - **Drag-over (dragenter active):** `border-accent border-solid bg-ternary-dark` (solid accent border, slight fill darkening). Copy switches to "Drop the file to upload."
  - **Error (post-rejection):** `border-red-400 border-solid` for 2 seconds after rejection, then fades back to idle. Inline error message below the dropzone (NOT inside it — the dropzone stays usable for retry).
- **After successful drop:** Dropzone height collapses to `min-h-0 p-4`, replaced by a single-line summary card: `[FiFile icon] {filename} · {size formatted} · [Replace file]`. The "Replace file" button reopens the file picker (re-uses `<input type="file">` ref). Geometry-summary panel renders below.
- **Constraints line** (always visible above the dropzone, idle and active): "Max 25MB. Files are read in your browser — they're not uploaded anywhere unless you submit." Renders in `text-sm text-ternary-section-dark`. Per QTE-03, constraints MUST appear before the visitor touches a file — this line satisfies that.
- **Format chips** (above the dropzone, below the constraints line): `<span className="inline-block px-2 py-1 rounded bg-secondary-section-dark text-primary-light text-xs font-general-medium uppercase tracking-wide">STL</span>` style — matches FAQ collapsible-detail card aesthetic. 3D tab shows `STL` + `OBJ`; laser tab shows `SVG`. (Forward-compat note: when DXF/3MF land in a later plan, they're added to the same chip row — no layout change.)
- **File picker fallback:** The dropzone is an `<label htmlFor="quote-file">` wrapping a hidden `<input type="file" id="quote-file" accept="{tab-specific MIME types}" className="sr-only">`. Click anywhere on the dropzone → browser file picker opens. Works on touch devices (no drag-and-drop) without separate UI.

### Geometry readout panel

- **Format:** Definition-list rhythm using `<dl>` with `<dt>` (label) + `<dd>` (value) pairs. NOT a card grid (one card per metric is too much visual chrome for 4-5 numbers); NOT a table (introduces a header row with no value).
- **Container:** `bg-ternary-dark rounded-xl p-6 mt-6` — matches `FAQ.jsx:60` `bg-secondary-section-dark p-6 rounded-xl` panel aesthetic, but darker fill so it reads as "data" not "control".
- **Row layout:** Two-column `<dl className="grid grid-cols-[max-content_1fr] gap-x-6 gap-y-3">` — labels left, values right, 12px row gap, 24px column gap. Labels are `text-sm font-general-regular text-ternary-section-dark`; primary values are `text-base font-general-medium text-primary-light`; secondary values (e.g. in³ beneath cm³) are `text-sm text-ternary-section-dark` directly under the primary.
- **"Computing…" state:** Same panel, same layout, but each `<dd>` shows a `text-ternary-section-dark` shimmer placeholder (`<span className="inline-block w-16 h-4 bg-secondary-section-dark/50 rounded animate-pulse">`). Section heading reads "Reading your file…" instead of "Geometry summary". `framer-motion` not required — Tailwind `animate-pulse` is sufficient and already in the codebase (no new utility needed).
- **Unit-interpretation warning (laser only, surfaced when SVG `viewBox`/`width`/`height` can't confirm mm):** Inline note **inside the geometry panel, directly under the bounding-box row** — NOT a separate banner. Style: `text-sm text-ternary-section-dark mt-2` with a subtle `border-l-2 border-ternary-section-dark pl-3` left rail to mark it as a footnote. Copy from §Copywriting Contract.

### Material + quantity picker (Plan 03-02+)

- **Material dropdown:** Native `<select>` reusing the exact `ContactForm.jsx:170-186` styling (`w-full px-5 py-2 border border-gray-300 dark:border-primary-dark border-opacity-50 text-primary-dark dark:text-secondary-light bg-ternary-light dark:bg-ternary-dark rounded-md shadow-sm text-md`). NO custom dropdown component — native `<select>` is accessible by default, picks up `@tailwindcss/forms` styling, and matches the Phase 2 D-25 `SERVICES`-driven dropdown precedent.
- **Material data flow:** GROQ via `useSanityQuery`: `*[_type == "material" && $serviceKey in services] | order(order asc){ _id, title, ... pricing rule fields ... }`. Reuses the Phase 2 `MaterialsSection.MATERIALS_QUERY` shape; extended with the `pricing-rule` reference fields when QTE-06 lands.
- **Material picker placement:** Below the geometry summary panel, above the price range. Form flow is top-down: file → geometry → material → quantity → estimate → submit. No accordions, no expand/collapse — every step is visible once the prior step is complete (steps that aren't ready yet are hidden, not disabled).
- **Quantity input:** `<input type="number" min="1" max="999" defaultValue="1">` styled identically to `FormInput.jsx`. Compact width (`w-24`), label above. Increments via keyboard or browser-native steppers; no custom + / − buttons.
- **Empty/loading states:**
  - Loading (Sanity hasn't returned yet): material `<select>` is disabled with placeholder text "Loading materials…".
  - Empty (Sanity returned `[]` for this service): replace the `<select>` with the empty-state copy from §Copywriting Contract (link to `/contact`). Quantity input hidden until materials exist. Price range hidden. Submit CTA disabled.

### Price-range display (Plan 03-02+)

- **Layout:** `<div className="mt-8 mb-2 flex items-baseline gap-3">` with the heading on one line and the range numeric on a separate larger-sized line below. Heading: `text-base font-general-medium text-ternary-light` "Ballpark estimate". Range value: `text-3xl sm:text-4xl font-display font-bold text-accent` (the only non-CTA accent application — see §Color).
- **Format:** Em-dash separator, dollar prefix, no decimals up to $1,000 (`$24 – $32`), one decimal kilo-suffix above (`$1.2k – $1.5k`). Helper: pure-JS `Intl.NumberFormat` — no new dep.
- **Disclaimer placement:** Directly below the range, `text-sm text-ternary-section-dark mt-2` (matches `ContactForm.jsx:230` muted-microcopy pattern). NEVER dismissable. NEVER moved into a tooltip or modal — has to remain on-screen at the moment the visitor sees the number, or the legal posture is broken (REQUIREMENTS.md QTE-05).
- **Update animation:** When the range value changes (because material or quantity changed), `framer-motion` `<motion.span key={`${low}-${high}`} initial={{ opacity: 0 }} animate={{ opacity: 1 }} transition={{ duration: 0.15 }}>` — quick fade. No counting-up animation (`react-countup` is in deps but is for `AboutMeBio` social-proof feel; misuse here would feel gimmicky on a price).
- **Owner-confirmation-required reminder** (above the submit CTA, separate from the price-disclaimer): `text-sm text-ternary-light` reading "We'll review your file and reply with a real quote — usually within 1 business day." Pulls `responseTimePromise` from `studio-info` Sanity singleton when Plan 03-02+ wires it (matches Phase 2 D-27); falls back to the literal "1 business day" text if Sanity returns null.

### Submit affordance + states

- **Plan 03-01 placeholder:** Disabled button styled as primary CTA — `<button disabled className="font-general-medium px-5 py-2.5 text-white bg-accent/40 cursor-not-allowed rounded-md mt-6">Submit for confirmation — coming soon</button>`. Adjacent muted helper: "We're still building the submission flow. In the meantime, you can [contact us](/contact) directly." — keeps the surface honest (D-02: site stays deployable; D-03: visitor doesn't hit a broken submit). Planner may swap to a real `<Link>` styled as primary CTA pointing at `/contact?service={key}&from=quote` if they prefer that read; document the choice in `03-01-PLAN.md`.
- **Plan 03-02+ submit states:**
  - **Idle:** `<button className="font-general-medium w-full sm:w-auto px-5 py-2.5 text-white bg-accent hover:bg-accent-highlight focus:ring-1 focus:ring-accent rounded-md mt-6 duration-500">Send this for a real quote</button>` (mirrors `ContactForm.jsx:219-225`).
  - **Loading:** `disabled` flag toggles the button to `bg-accent/60 cursor-not-allowed`, copy switches to "Sending…", no spinner icon.
  - **Success:** Whole form panel is replaced by the success state copy from §Copywriting Contract — full-form replacement matches `ContactForm.jsx:84-99`. NO modal, NO redirect. The page stays at `/quote`; visitor scrolls or navigates away on their own.
  - **Failure:** Inline `<p className="mt-4 text-sm text-red-400" role="alert">...</p>` directly below the (still-clickable) button — matches `ContactForm.jsx:235`. Visitor can retry from the same form state without losing their inputs.
- **No confirmation dialog before submit.** Submission is non-destructive (just an email to the owner); a confirm modal would add friction without value. The "estimate, not a binding quote" disclaimer + owner-confirmation reminder already make the non-binding nature visible.

### Disclaimer placement (legal posture, locked)

| Surface | Placement | Copy | Style |
|---------|-----------|------|-------|
| Page subhead | First paragraph below H1 | "We give you a quick range so you can decide if it's worth a real quote. Final price comes after we look at your file." | `text-base text-ternary-light` |
| Below price range | `text-sm`, never dismissable | "This is an estimate. Final price comes after we review your file — not a binding quote." | `text-sm text-ternary-section-dark mt-2` |

### Error states + validation copy

| Error type | Where it appears | Style | Dismissable |
|------------|------------------|-------|-------------|
| File format mismatch | Inline below dropzone, `role="alert"` | `text-red-400 mt-2 text-sm`, no banner | Auto-clears when a valid file replaces it |
| File too large | Inline below dropzone, `role="alert"` | Same as above | Auto-clears on retry |
| Malformed file (parse failure) | Inline below dropzone | Same as above | Auto-clears on retry |
| SVG unit warning | Inline inside geometry panel (NOT a banner) | `text-sm text-ternary-section-dark` muted note (NOT red — this is a *warning*, not an *error*; the parse succeeded) | Persists while the SVG is loaded; clears when a different file is dropped |
| Submit failure | Inline below the submit button | `text-sm text-red-400 role="alert"` | Persists until visitor retries or fixes |
| reCAPTCHA failure (Plan 03-02+) | Inline below submit button | Same as submit failure | Same |
| Network offline (Plan 03-02+) | Same | Same | Same |
| Sanity material fetch failure (Plan 03-02+) | Replace the picker with the empty-state copy + "Try again" inline button | `text-sm text-ternary-section-dark` | "Try again" re-runs the query |

**Tone rules for errors:** No stack traces, no raw error names ("Error: NetworkError when attempting to fetch resource"). Always tell the visitor what went wrong AND what to do next. The "next step" is usually "try again" or "contact us" — never "check the console" or "refresh the page".

### localStorage persistence UX (Plan 03-02+, QTE-10)

- **What's persisted:** active tab key (`laser` | `print`), selected material `_id`, quantity number. **NOT persisted: the file itself** (FileReader can re-read on next visit but `File` objects can't survive a refresh; localStorage size cap also makes it impractical).
- **Restore behavior:** On `/quote` mount, read localStorage; if a stored selection exists, set the tab + material + quantity from it. Show a subtle banner above the tab strip: "We restored your last selections. [Start over]" — `text-sm text-ternary-light` with the "Start over" as an inline text button (`underline hover:text-primary-light`). Banner auto-dismisses after first user interaction (clicking a tab, changing material, etc.) — banner is a one-time confirmation that state was restored, not a persistent UI element.
- **Clear behavior:** "Start over" button removes the localStorage entry, resets tab to default, clears material and quantity. NO confirmation dialog — the action is cheap and reversible (visitor can re-select).
- **Auto-clear after submit:** On successful submission, localStorage entry is cleared in the same handler that flips the success state. Prevents the next visitor on the same browser from seeing stale "we restored your selections" UI.
