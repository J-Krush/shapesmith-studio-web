Mock shape — `sanityClient` is the default export of `src/utilities/sanityClient.jsx`:

```js
jest.mock('./utilities/sanityClient', () => ({
  __esModule: true,
  default: {
    fetch: jest.fn(() => Promise.resolve([])),
  },
}));
```

The `__esModule: true` flag is required because the wrapper uses ES module `export default` and `react-scripts test`'s Jest config (CRA's babel-jest) interops between ESM and CJS via this flag.

Assertion: `await screen.findAllByText(/contact/i)` — the persistent header renders a `Contact` `<Link>` in BOTH the mobile nav and the large-screen nav (`AppHeader.jsx` lines 128, 182 in current state). At least one match is guaranteed at any viewport size in jsdom. The test is `async` and uses `findAllByText` (not `getAllByText`) by default because the mocked `fetch` returns `Promise.resolve([])`, which guarantees a microtask deferral — synchronous queries would fire before the hook's `setData` call had flushed and could surface React `act()` warnings.

Indentation: 2-space (matches the existing `src/App.test.js` and CRA boilerplate convention; tabs would also work but 2-space matches the file's pre-existing style and is less disruptive in diffs).

`src/setupTests.js` already exists and imports `'@testing-library/jest-dom'` — no change needed there.

Verbatim replacement body (per PATTERNS.md §"Suggested replacement body" with the Option A correction AND async-by-default per Warning #8 fix):

```jsx
import { render, screen } from '@testing-library/react';
import App from './App';

jest.mock('./utilities/sanityClient', () => ({
  __esModule: true,
  default: {
    fetch: jest.fn(() => Promise.resolve([])),
  },
}));

test('App mounts without crashing and renders persistent nav', async () => {
  render(<App />);
  // Header nav renders a Contact link in both the mobile and large-screen variants.
  // At least one match must appear in jsdom regardless of viewport.
  // `findAllByText` (async) is used because the mocked fetch returns Promise.resolve([])
  // which defers `setData` to a microtask — synchronous getAllByText would race the resolve
  // and could surface React act() warnings.
  const contactLinks = await screen.findAllByText(/contact/i);
  expect(contactLinks.length).toBeGreaterThan(0);
});
```

Note on the assertion: `findAllByText(/contact/i)` (not `findByText`) is used because the header renders TWO `Contact` links (one for mobile menu, one for desktop). `findByText` would throw `Found multiple elements`. `findAllByText` accepts >=1 match AND awaits the next render cycle so the hook's mocked fetch resolves cleanly; combined with the `.length > 0` assertion this both proves mount success AND that the persistent nav rendered without `act()` warnings.
