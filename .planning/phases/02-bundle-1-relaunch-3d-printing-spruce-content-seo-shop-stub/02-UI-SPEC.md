## Spacing Scale

The project already uses Tailwind's default 4-pt spacing scale (`p-2` = 8px, `p-4` = 16px, `p-6` = 24px, etc.). **Do not redefine these in `tailwind.config.js`** — D-09 commits to a token diff for spruce, but the spacing scale is not part of the diff. We declare a section-rhythm contract per the 8-point system so executors know which scale steps to reach for.

| Token | Tailwind class | Value | Usage |
|-------|----------------|-------|-------|
| xs | `p-1`, `gap-1` | 4px | Icon-to-text gap inside a button or pill |
| sm | `p-2`, `gap-2` | 8px | Compact element spacing (form-row internal padding, badge padding) |
| md | `p-4`, `gap-4` | 16px | Default element spacing — card body padding, list-item gap |
| lg | `p-6`, `gap-6` | 24px | Card outer padding, in-card section breaks |
| xl | `p-8`, `mt-8` | 32px | Layout gaps between sibling components, hero-vs-next-section break |
| 2xl | `py-12`, `mt-12` | 48px | Major section breaks on a page (between hero, services, materials, FAQ, etc.) |
| 3xl | `py-24`, `mt-24` | 96px | Page-level rhythm (top-of-page padding before hero on some routes) — already in use in `Home.jsx` |

**Section rhythm contract for the relaunch sweep (D-09 token-first, D-10 dual-service hero):**

- Page top → hero block: `mt-12 sm:mt-24` (matches existing `Home.jsx` `mt-24` rhythm)
- Hero → next section: `mt-24` (3xl) on desktop, `mt-12` (2xl) on mobile
- Section → section (inside a route): `py-12` to `py-24` outer wrapper depending on hierarchy
- In-card padding: `p-6` (lg) default; `p-8` (xl) only for hero-tier cards
- Container horizontal padding: keep existing `tailwind.config.js` `container.padding` scale (`1rem` / `2rem` / `5rem` / `6rem` / `8rem` at sm/lg/xl/2xl)
- CTA button vertical padding: `py-2.5` (existing pattern); horizontal `px-5` (existing pattern); minimum touch target ≥ 44px tall — already satisfied by `py-2.5 + text-md` line height

**Exceptions:**
- Hero placeholder cards (D-11) use a fixed `aspect-square` or `aspect-[4/3]` ratio — height is content-driven, not a spacing token.
- Modal scrim padding follows `framer-motion` conventions inside `ProjectGallery.jsx` (state-driven post-Phase 1) — no new spacing tokens introduced.
- Existing `mt-24` / `mb-24` calls in `AppBanner.jsx` are preserved during the hero refresh; they're part of the inherited rhythm, not a deviation.

## Typography

**Locked — no churn this phase (D-08).** Project uses self-hosted GeneralSans variable font + named weights (Extralight, Light, Regular, Medium, Semibold, Bold) plus the existing `font-display` / `font-general-medium` / `font-general-regular` / `font-general-variable` / `font-general-extralight` utility classes. No new families. No size-token changes in `tailwind.config.js`.

Sizes below are picked from Tailwind's existing scale and the patterns already shipped in `AppBanner.jsx`, `Home.jsx`, `ProjectSingle.jsx`, `ContactForm.jsx`. Executors reach for these classes during the per-route sweep — they are not re-defined.

| Role | Tailwind class | Size | Weight | Line Height | Usage |
|------|----------------|------|--------|-------------|-------|
| Body | `text-base` (`text-md` in some files) | 16px | `font-general-regular` (400) or `font-general-variable` | 1.5 (Tailwind default `leading-normal`) | Default paragraph copy in service descriptions, FAQ answers, trust copy blocks, contact-form labels |
| Label / Small | `text-sm` | 14px | `font-general-medium` (500) | 1.5 | Field labels, captions on placeholder cards (D-11), tag labels (e.g., "Laser" / "Print" badges on materials), nav link active-state hint |
| Lead / Subhead | `text-xl` | 20px | `font-general-medium` (500) | 1.4 | Hero subhead, section intro paragraph, contact-form heading (`text-2xl` is the existing `ContactForm.jsx` choice — preserve) |
| Heading (H2) | `text-2xl sm:text-3xl` | 24px → 30px | `font-display` Bold (matches existing `Home.jsx` / `Shop.jsx` patterns) | 1.2 | Section headings on service pages (Materials, FAQ, "What we won't make", trust copy header) |
| Display (H1) | `text-3xl sm:text-4xl` | 30px → 36px | `font-display` Black (matches existing hero `font-display font-black`) | 1.1 | Hero H1 on `/`, page title on `/styles`, `/3d-printing`, `/shop`, `/404` |

**Body line-height:** `leading-normal` (Tailwind 1.5) for paragraph copy. Confirmed via `AppBanner.jsx:47` (`leading-normal`).
**Heading line-height:** `leading-tight` (Tailwind 1.25) for H1; `leading-snug` (1.375) for H2. Tightening only where existing `font-display font-black` has visual weight that needs it.

**Italics / emphasis:** use existing `font-general-italic` / `font-general-variable-italic` utility classes only when content semantically requires it (e.g., the `*Metal cutting available via...` line in `QuickInfo.jsx`). Do not italicize for visual interest.

**Per-route copywriting ladder:** The hero is the only display-tier element on the homepage; all interior pages use H1 (`text-3xl sm:text-4xl`) → H2 (`text-2xl sm:text-3xl`) → Body. Two heading levels max per page. Avoid stacking `text-4xl` and `text-3xl` siblings — that's an alignment-of-importance failure mode the spruce should fix.

### Accent reserved for (explicit list — never "all interactive elements"):

1. **Primary CTAs that move the visitor toward conversion:**
   - `Contact` button in nav (`AppHeader.jsx`) — already accent
   - `Send` submit button on `ContactForm.jsx` — currently `bg-indigo-500`; swap to `bg-accent` during sweep
   - `Notify me when it launches` button on `/shop` Coming Soon (D-23)
   - "See materials" anchor link on each service page (D-17) — accent text-color treatment, not full button
   - The "Get in touch" / "Contact" CTA, if surfaced from a service page, uses accent

2. **Active-state nav indicator** for the current route: small underline or dot in `accent` color under the active nav link. Subtle — not a full pill background.

3. **Selected state** on the contact form's `service` dropdown when it's been pre-filled from referrer (D-24): a 1-pixel `border-accent` outline to signal "we picked this for you, you can change it." Optional polish — drop if it adds executor work.

**NOT accent:**
- Body links inside paragraph copy → use existing `dark:text-primary-light` with `underline` on hover (no color change). The current `QuickInfo.jsx` `hover:text-indigo-300` is template residue and should become `hover:text-accent` during sweep — but the resting state stays neutral.
- Material cards, project cards, gallery thumbs → no accent fill. They live in the secondary-30% band.
- Hero brand wordmark image → no accent overlay.
- Section dividers → no accent. Use `border-secondary-section-dark` if a divider is needed.
- Decorative borders, shadows, icons → no accent.

### Color contrast acceptance (CNT-04 + a11y baseline):

- All body text on `primary-dark` background must meet WCAG 2.1 AA 4.5:1 — `dark:text-primary-light` (`#F7F8FC` on `#291c30`) clears this.
- All body text on `ternary-dark` card surface must clear 4.5:1 — `dark:text-ternary-light` clears this.
- Accent button text uses `text-white` on `bg-accent` (`#348bd8`) — clears 4.5:1 for normal text per WebAIM.
- Form-error red on dark surfaces uses Tailwind `red-400` (not `red-500`) when on `primary-dark`/`ternary-dark` — small contrast bump for legibility.

### Photography placeholder color (D-11):

When a Sanity image field is empty on a `print-style` (and any `laser-style` that lacks photos), render a **stylized branded placeholder card** instead of a broken image. Placeholder visual:
- Background: `bg-secondary-section-dark` (`#594a60`) — distinct from the page surface so the placeholder reads as intentional, not as "image failed to load"
- Centered icon: `FiImage` from `react-icons/fi` at `text-4xl` in `dark:text-ternary-light` opacity-50
- Caption below icon: `text-sm font-general-medium text-ternary-light opacity-80` — for `print-style`: "3D print example coming soon"; for `laser-style`: "Laser cut example coming soon"
- Aspect ratio: matches the photo it replaces (`aspect-square` for grid cards, `aspect-[4/3]` for detail-page galleries)
- No accent on the placeholder — it sits in the secondary band so the page still reads as photo-driven once real photos arrive

**Why these specifics:** The placeholder must look intentional even when 80% of the `/3d-printing` grid uses it at launch (per D-12 — photo session is parallel non-code work). A muted secondary-band color + a clear caption signals "we know, real photos coming" rather than "this site is broken."

### Hero composition (D-10 — researcher recommendation, planner may refine)

D-10 commits to "split-or-stacked dual-service framing, 50/50 on desktop, stacked on mobile, equal visual weight." Within that constraint the researcher recommends the following composition for the new `AppBanner.jsx`:

**Layout (desktop, ≥`sm`):**

```
┌───────────────────────────────────────────────────┐
│ [brand wordmark image — full width, centered]     │
│                                                   │
│ <H1>                                               │
│   Maker Studio — Custom Laser Cutting              │
│   & 3D Printing                                    │
│ </H1>                                              │
│                                                   │
│ <p subhead>                                        │
│   No idea too big or too small. We cut, engrave,  │
│   and now print the things you have in mind.       │
│ </p>                                               │
│                                                   │
│ ┌─────────────────────┬─────────────────────────┐ │
│ │  LASER CUTTING      │  3D PRINTING            │ │
│ │  ──────────────     │  ──────────────         │ │
│ │  hardwood, plywood, │  PLA, PETG, TPU, more   │ │
│ │  acrylic, leather…  │                         │ │
│ │                     │                         │ │
│ │  See examples →     │  See examples →         │ │
│ └─────────────────────┴─────────────────────────┘ │
└───────────────────────────────────────────────────┘
```

- Both service panels are equal-width cards (`w-full sm:w-1/2`), same height, same padding, same border-radius (`rounded-xl` — matches existing `ProjectSingle.jsx` card pattern).
- Each card has: service name (H2-tier `text-2xl font-display font-black`), a one-line material list, a single text-link "See examples →" pointing to `/styles` or `/3d-printing` respectively. **Equal visual weight is non-negotiable per SVC-03 + VIS-01.**
- Surface color: both cards `dark:bg-ternary-dark` (secondary-30%). No accent fill on either — that would weight one over the other.
- The "Contact us" primary CTA sits **below** the two cards, centered, full accent — single shared CTA so neither service feels favored.

**Layout (mobile, <`sm`):**

The two service cards stack vertically, full-width each. Order: Laser first (existing service), then Print (new service). This is conventional reading order, not a value judgment — both still get equal visual weight (same card style, same size).

**Why this composition:**
- Visual confidence (the core value) comes from a clean, balanced split, not from photography we don't have.
- The single "Contact us" CTA below the split avoids accent-fight between the two service cards.
- "See examples →" is a plain text-arrow link, not a button — it routes to the service page where the visitor sees real work (or branded placeholders).
- The brand wordmark image (`brand-horizontal-multi-font.png`) stays — it's the existing identity element and keeps continuity.
