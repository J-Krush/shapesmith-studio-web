<!-- Existing Sanity schemas the new `product` schema cross-references via reference fields. Spec must mirror the field-naming conventions established in Phase 2. -->

The existing `process` enum doc (Phase 2) is referenced by `material.processes` and is to be reused for `product.processes`. Each process doc has shape:
```
{ _type: 'process', name: string, key: 'laser' | 'print', _id, _rev }
```
GROQ deref pattern (in product context query):
```
"processes": processes[]->key
```

The existing `material` document (Phase 2) shape (relevant fields only):
```
{ _type: 'material', name: string, slug: { current: string }, services: ('laser' | 'print')[], processes: reference[] (laser ops) }
```
GROQ deref pattern (in product context query):
```
"materials": materials[]->{ _id, name, "slug": slug.current, services }
```

The existing `studio-info` singleton (Phase 2) provides the per-product leadTime fallback:
```
{ _type: 'studio-info', shippingLeadTime: string, ...other fields }
```

The Snipcart `data-item-*` attribute contract that the schema must support (consumed in Plan 03's AddToCartButton):
- data-item-id: product.slug.current (kebab-case stable identifier)
- data-item-name: product.name
- data-item-price: product.price as Number(price).toFixed(2)
- data-item-description: product.description (≤200 chars)
- data-item-image: urlAt(product.images[0], 800) — REQUIRES product.images to be a non-empty array of objects with `asset` references
- data-item-categories: product.processes.map(p => p.key).join('|')  — pipe separator (NOT comma; Snipcart docs verified)
- data-item-max-quantity: product.stockQuantity (integer)
</interfaces>
