## Spacing Scale

The codebase uses Tailwind's default 4px-base scale (`p-1`, `p-2`, `p-4`, `p-6`, `p-8`, `p-10`, `p-12`) plus the container-padding overrides in `tailwind.config.js`. Phase 5 stays on this scale — no new spacing tokens.

| Token | Tailwind class | px | Usage in Phase 5 |
|-------|----------------|----|-------------------|
| xs | `p-1` / `gap-1` | 4 | Icon-to-text gap inside small badges, tight inline padding |
| sm | `p-2` / `gap-2` | 8 | Spec-table row padding, badge inner padding, thumbnail gaps in gallery |
| md | `p-4` / `gap-4` | 16 | Card inner padding (image-to-meta gap), filter pill gaps |
| lg | `p-6` / `gap-6` | 24 | Card outer padding on `/shop/:slug`, info-column section gaps |
| xl | `p-8` / `gap-8` | 32 | Grid `gap` between cards on tablet+, info-column header → price spacing |
| 2xl | `p-12` / `mt-12` | 48 | `<section>` vertical padding (matches `Shop.jsx` `py-12 sm:py-24`), grid → spec-table separator |
| 3xl | `mt-24` / `py-24` | 96 | Page-level top spacing on tablet+ (mirrors `Shop.jsx` Coming Soon, `Home.jsx` `mt-24`) |

**Container padding** (inherited from `tailwind.config.js` extend): `1rem` mobile, `2rem` `sm:`, `5rem` `lg:`, `6rem` `xl:`, `8rem` `2xl:`. Phase 5 uses `<div className="container mx-auto">` exactly like `ServicesGrid.jsx:9`.

**Sticky-mobile Add-to-Cart bar height:** 64px (= `h-16`, multiple of 8). Tap target 48px minimum (D-12 mobile primary action).

**Exceptions:** none. Phase 5 introduces zero new spacing primitives.

## Typography

The project's existing typographic system (PROJECT.md + `src/css/App.css` font-face declarations) gives us font families and weights. Phase 5 uses 4 sizes + 2 weights, all sourced from the established type scale.

| Role | Size (Tailwind) | px | Weight | Font family | Line height | Used for |
|------|-----------------|----|--------|-------------|-------------|----------|
| Display | `text-4xl sm:text-5xl` | 36 → 48 | font-black (900) via `font-display` (Proxima Nova) | Proxima Nova / `font-display` | `leading-tight` (1.25) | Product name `<h1>` on `/shop/:slug` (mirrors `AppBanner` H1 / `Shop.jsx` h1 cadence) |
| Heading | `text-2xl sm:text-3xl` | 24 → 30 | semibold (600) via `font-general-semibold` | GeneralSans-Semibold | `leading-snug` (1.375) | `/shop` page heading ("Shop"), section titles inside detail page (e.g. "Details", "Materials") |
| Body | `text-base` | 16 | regular (400) via `font-general-regular` | GeneralSans-Regular | `leading-relaxed` (1.625) | Product card name, body copy, spec-table values, filter pill labels |
| Small | `text-sm` | 14 | medium (500) via `font-general-medium` | GeneralSans-Medium | `leading-normal` (1.5) | Sold-out badge, "Only N left" tag, spec-table labels, filter aria-labels, helper text |

**Price typography (special case — Phase 5 specific):** `text-3xl sm:text-4xl` (30 → 36 px) at weight regular (400) using `font-general-regular`, color `text-primary-light`. Large enough to be the second-largest element on the detail page after the product name; not bold, because the page already has heavy display weight on the product name and we don't want the price to compete. On the grid card, price is `text-lg` (18 px) regular.

**Font-weight inventory (exactly 2 weights for body/UI text):**
- regular (400) — `font-general-regular` for everything
- medium (500) — `font-general-medium` for emphasized small text and buttons (matches existing site usage)

The `font-display` (Proxima Nova) at black (900) is used ONLY for product name `<h1>` on detail pages and the `/shop` page H1 — it is the existing site's display font and not an additional weight added for Phase 5.

### Sold-out + low-stock visual treatment (D-16 — locked, no animations)

| State | Treatment |
|-------|-----------|
| Available (default) | No badge, no overlay. Card image full-color. Add-to-Cart button = `bg-accent`. |
| Low stock (`1 ≤ stockQuantity ≤ 3` — threshold value is planner discretion per CONTEXT D-06; recommend `3`) | "Only N left" tag inline RIGHT of price (`ml-3 text-sm font-general-medium text-ternary-section-dark`). No badge on card image. Card image stays full-color. Add-to-Cart button stays `bg-accent`. |
| Sold out (`stockQuantity === 0`) | (a) "Sold out" badge top-left of image, `bg-secondary-section-dark text-ternary-light text-sm font-general-medium px-3 py-1 rounded-md`. (b) Image overlay `bg-secondary-section-dark/70` over the entire image, achieved by wrapping `<SanityImage>` in a `relative` div with an absolute-positioned `<div className="absolute inset-0 bg-secondary-section-dark/70 rounded-xl" />`. (c) Card opacity NOT reduced (badge + overlay carry the message; double-dimming washes out detail). (d) On detail page: Add-to-Cart button replaced with a static `<span>Sold out</span>` styled `bg-secondary-section-dark text-ternary-light px-5 py-2.5 rounded-md cursor-not-allowed font-general-medium` (matches button geometry so layout doesn't reflow). |

**No animations** on either state per D-16 — no `animate-pulse`, no `transition-opacity` on the badge, no countdown timers.

## Layout & Interaction Contracts (Phase 5 specific)

These answer the 12 open questions raised in the orchestrator prompt's `<additional_context>`. Each is prescriptive for the executor; deviations require a PLAN.md note.

### 1. `/shop` grid breakpoints + card aspect ratio

Mirror `ServicesGrid.jsx:35` and `ServiceCard.jsx:28` exactly. **Same column counts, same image aspect ratio.**

| Breakpoint | Tailwind | Columns |
|------------|----------|---------|
| Default (mobile <640px) | `grid-cols-1` | 1 |
| `sm:` (≥640px) | `sm:grid-cols-2` | 2 |
| `lg:` (≥1024px) | `lg:grid-cols-3` | 3 |

Row gap: `gap-y-10`. Column gap on `sm:`+ `sm:gap-x-10`. Mobile cards stack with `mb-10` between cards (matches `ServiceCard.jsx:21` `mb-10 sm:mb-0`).

Card image: `aspect-square object-cover rounded-xl` — identical to `ServiceCard.jsx:28`. Square thumbnails work for both laser-flat objects and 3D-printed objects without favoring one form factor.

Card structure (top → bottom):
```
<Link to={`/shop/${slug}`}>
  <div className="rounded-xl shadow-lg hover:shadow-xl bg-ternary-dark mb-10 sm:mb-0">
    <div className="relative">                       (← only when sold-out badge needed)
      <SanityImage ... className="aspect-square object-cover rounded-xl" />
      {soldOut && <span className="absolute top-3 left-3 ...">Sold out</span>}
      {soldOut && <div className="absolute inset-0 bg-secondary-section-dark/70 rounded-xl" />}
    </div>
    <div className="text-center px-4 py-6">
      <p className="font-general-medium text-lg text-ternary-light mb-2">{name}</p>
      <p className="font-general-regular text-lg text-primary-light">
        ${price.toFixed(2)}
        {lowStock && <span className="ml-3 text-sm text-ternary-section-dark">Only {n} left</span>}
      </p>
    </div>
  </div>
</Link>
```

Hover state: `hover:shadow-xl` (matches `ServiceCard.jsx:21`). No transform, no scale, no overlay reveal — keeps the card calm, matches site rhythm.

### 2. `/shop/:slug` image gallery interaction model

**Reuse the `ServiceGallery.jsx` interaction pattern verbatim** (D-12). Specifically:
- Thumbnails grid: 3-up wrap (matches `ServiceGallery.jsx:24` `w-1/3`). Each thumbnail is `aspect-[4/3] object-cover rounded-xl`.
- Click any thumbnail → opens a fullscreen `fixed inset-0 bg-black/70 z-80` lightbox with the image at `max-h-[90vh] max-w-[90vw] object-contain`. Close via top-right `&times;` button (`text-white text-5xl`).
- No zoom-on-hover, no pinch-zoom-in-lightbox, no carousel swipe between images in the lightbox (out of scope — stays on `ServiceGallery.jsx` parity).
- Layout placement: thumbnail grid is the LEFT column on `lg:` (≥1024px) at `lg:w-7/12`; STACKED ABOVE the info column on `<lg:` (mobile + tablet). The mobile-stacked variant places the image grid at the top so the visitor sees the product before the metadata — standard e-commerce convention.

Decision: **inline reuse `<ServiceGallery />` is NOT viable** because that component pulls from `useSingleService()` context. Instead, extract a thin `src/components/shared/ImageGallery.jsx` primitive that takes `images` and `placeholderCaption` as props, and refactor `ServiceGallery.jsx` to consume it. Both `/shop/:slug` and existing `/styles/:slug` + `/3d-printing/:slug` pages reuse the new primitive with zero visual change. (Planner judges whether to ship the refactor as a separate plan or as part of the detail-page plan.)

### 3. Sticky mobile Add-to-Cart anchor (D-12)

A footer-pinned full-width bar visible **only on `<md:` (`<768px`)** when the visitor has scrolled past the in-content Add-to-Cart button.

```
<div className="fixed bottom-0 left-0 right-0 md:hidden z-30
                bg-ternary-dark/95 backdrop-blur-sm border-t border-secondary-section-dark
                px-4 py-3 flex items-center justify-between">
  <div className="flex flex-col min-w-0 mr-3">
    <span className="text-sm font-general-medium text-ternary-light truncate">{name}</span>
    <span className="text-base font-general-regular text-primary-light">${price}</span>
  </div>
  <button className="snipcart-add-item bg-accent hover:bg-accent-highlight
                     text-white font-general-medium px-5 py-2.5 rounded-md
                     flex-shrink-0 disabled:opacity-50 disabled:cursor-not-allowed"
          data-item-id={...} data-item-price={...} ... >
    Add to Cart
  </button>
</div>
```

Visibility logic: `IntersectionObserver` watches the in-content Add-to-Cart button — when it scrolls out of view (above the viewport), show the sticky bar; when it scrolls back in, hide. Bar height = 64px (`py-3` + content ≈ 64px); add `pb-16 md:pb-0` to the page's bottom container so the last bit of content isn't covered. When sold out, the sticky bar still renders but the button is replaced with a static `<span>Sold out</span>` (cursor-not-allowed, no Snipcart class).

### 4. Sold-out badge placement + treatment

Already specified in the Color → Sold-out + low-stock visual treatment table above. Summary:
- Badge: top-left corner of image at `top-3 left-3`, `bg-secondary-section-dark text-ternary-light text-sm font-general-medium px-3 py-1 rounded-md`.
- Overlay: `absolute inset-0 bg-secondary-section-dark/70 rounded-xl` over the image (NOT the whole card — keeps the name + price below the image at full readability).
- Card opacity NOT reduced — just the image gets the overlay. Double-dimming makes detail unreadable.
- No animation.

### 5. Low-stock "Only N left" tag

Already specified above. Summary:
- Inline RIGHT of price on both grid card and detail page: `<span className="ml-3 text-sm font-general-medium text-ternary-section-dark">Only {n} left</span>`.
- Color: `text-ternary-section-dark` (`#94989c`) — muted, NOT accent (D-16: no urgency animations, no urgency colors).
- No background, no border, no badge styling — just inline text.

### 8. Add-to-Cart button — detail page (in-content variant)

> **Separator note (corrected):** `data-item-categories` uses the pipe `|` separator
> per `docs.snipcart.com/v3/setup/products`. An earlier draft of this section used
> a comma — that has been corrected. With pipe, `["laser", "print"]` becomes the
> attribute value `"laser|print"` and Snipcart's category analytics see two
> distinct categories (otherwise it'd see one category named `"laser,print"`).

```
<button
  className="snipcart-add-item
             bg-accent hover:bg-accent-highlight text-white
             font-general-medium px-6 py-3 rounded-md
             text-base sm:text-lg
             duration-300
             disabled:opacity-50 disabled:cursor-not-allowed"
  data-item-id={slug}
  data-item-name={name}
  data-item-price={price.toFixed(2)}
  data-item-url={`https://shapesmith.studio/shop/${slug}`}
  data-item-image={imageCDN}
  data-item-description={description}
  data-item-categories={processes.join('|')}
  data-item-max-quantity={stockQuantity}
  data-item-stackable={stockQuantity > 1 ? 'auto' : 'never'}

  Add to Cart
</button>
```

Width: natural width on tablet+ (button hugs its content); full-width (`w-full`) on mobile (`<sm:`) to maximize tap target. Disabled state when `stockQuantity === 0` is replaced with the static `<span>Sold out</span>` per D-16 — same geometry, no `<button>` element rendered (semantic correctness: a sold-out item has no purchase action).

Sticky-mobile variant: same `bg-accent` + `hover:bg-accent-highlight` colors, smaller `px-5 py-2.5`, `flex-shrink-0`. See section 3 above for the full bar.

### 9. Empty-state visual + auto-flip transition (D-13)

The empty state IS the existing `Shop.jsx` Coming Soon page (preserved exactly; see Copywriting Contract rows). When `count(*[_type=='product']) > 0`, the page auto-flips to the catalog grid.

**Implementation pattern:** the new `Shop.jsx` runs `useSanityQuery` for `*[_type=='product']{...}`. While loading, render `null`. When `data.length === 0`, render the existing Coming Soon JSX (extracted to `<ShopComingSoon />` so both Phase 2 and Phase 5 share the same component — the existing form, copy, SEO, and submit logic survive untouched). When `data.length > 0`, render the new `<ShopCatalog products={data} />`.

**No transition between states needed.** The flip is one-shot (owner publishes the first product → the very next visitor's fetch returns 1+ products → catalog renders). No need for a fade/crossfade; it's not an in-session state change.

**SEO behavior at the flip point:** SEO `<title>` and `description` for `/shop` are the same in both branches (the Coming Soon copy is generic enough to apply once products exist — "Pre-made laser-cut and 3D-printed pieces, ready to take home"). No additional SEO logic needed for the auto-flip.

**`shop-notify` form preservation:** the Netlify form declaration in `index.html` (D-28) and the `<form name="shop-notify">` in the React tree both must keep working in the empty-state branch. Phase 5 adds no new Netlify Forms.

### 10. Loading states

**Match site convention: `useSanityQuery` returning `data === undefined` → render `null`.** No skeleton cards, no spinner. This matches Phase 2's `MaterialsSection.jsx`, `FAQ.jsx`, and every other Sanity-driven surface in the codebase. Adding skeletons would be an inconsistency with the rest of the site.

**Exception:** if the planner observes a noticeable layout-shift jolt on the deploy preview when products land (because the page is initially empty then suddenly fills with cards), the planner MAY add a `min-height: 60vh` container around the grid to reserve space. But this is pre-emptive only — don't ship it without observing the jolt.

### 11. Spec table (`Details` section at bottom of right column on detail page)

A two-column key:value definition list, NOT a `<table>` element (it's not tabular data; it's metadata pairs).

```
<dl className="border-t border-secondary-section-dark mt-12 pt-6 grid grid-cols-[max-content_1fr] gap-x-6 gap-y-3">
  <dt className="text-sm text-ternary-section-dark font-general-medium uppercase tracking-wide">Dimensions</dt>
  <dd className="text-base text-ternary-light">{product.dimensions}</dd>

  <dt className="text-sm text-ternary-section-dark font-general-medium uppercase tracking-wide">Materials</dt>
  <dd className="text-base text-ternary-light">
    {product.materials.map((m, i) => (
      <Link key={m._id} to={materialAnchor(m)} className="underline hover:text-accent duration-500">
        {m.name}
      </Link>
    )).reduce((acc, el, i) => i === 0 ? [el] : [...acc, ' · ', el], [])}
  </dd>

  <dt className="text-sm text-ternary-section-dark font-general-medium uppercase tracking-wide">Ships in</dt>
  <dd className="text-base text-ternary-light">{product.leadTime ?? studioInfo.shippingLeadTime}</dd>
</dl>
```

The `<dt>` (label) column gets `max-content` so labels self-size and the value column fills remaining width. `gap-x-6` (24px) keeps label and value visually separated without a divider. Top border on the `<dl>` separates the spec block from the body copy / portable-text above.

If `product.materials` is empty, omit the row entirely (don't render an empty Materials line).
If `product.dimensions` is empty, omit the row.
If `product.leadTime` and `studio-info.shippingLeadTime` are both empty, render the fallback copy from the Copywriting Contract.

### 12. `/shop` SEO og:image

**Decision: stay on `/og-default.png`** (the brand wordmark from Phase 2). Rationale: link previews to `/shop` happen before any specific product is in the visitor's mind; a brand image is the most consistent first impression. When a visitor shares a specific product link (`/shop/:slug`), THAT page's og:image is the product's first image (already specified in the Copywriting Contract row). This split keeps the catalog landing branded and the per-product pages product-focused.
