  <name>Task 2: Walk the Netlify deploy preview and sign off on parity with production</name>
  <what-built>
Plans 04-01..04-05 produced a Vite-built bundle that should behave identically to the prior CRA-built bundle from any user's perspective. Local `pnpm build` succeeds and `pnpm test` is green. The Netlify deploy preview is the only environment where end-to-end behavior (Netlify Forms detection, redirects, real reCAPTCHA, real Sanity CDN reads, real CDN asset serving) can be verified before merging to production.
  </what-built>
  <how-to-verify>
1. **Push the branch to GitHub.** From the repo root: `git push -u origin <branch-name>` (whatever branch Plans 04-01..04-05 were committed on). Netlify auto-creates a deploy preview within 2-5 minutes.

2. **Find the deploy preview URL.** Netlify dashboard -> Deploys -> the new deploy entry for the branch -> "Deploy preview" URL (typically `https://deploy-preview-NN--shapesmith-studio-web.netlify.app` or similar).

3. **Confirm the build succeeded.** The deploy log should show:
   - `pnpm install` succeeds (Vite, plugin-react, vitest, jsdom installed).
   - `pnpm build` runs `vite build` (NOT `react-scripts build`) and produces `build/`.
   - `node scripts/generate-sitemap.cjs` runs as `postbuild`.
   - Netlify Forms registration scan runs against `build/index.html` and detects `contact-form` + `shop-notify`.

4. **Walk the deploy preview** — visit each URL and verify the listed behavior. RESEARCH.md section "## Project Constraints (from CLAUDE.md)" says the dominant constraint is "behaves identically to the CRA build from any user's perspective."

| URL | Expected behavior |
|-----|-------------------|
| `/` | Home page loads with dual-service hero (laser + 3D printing); nav shows both services peer-equal; no console errors; dark theme applied |
| `/styles` | Laser styles grid renders; Materials section visible; FAQ + WontMake + TrustCopy blocks present |
| `/styles/<any-slug>` | Single-style page renders with image gallery; click an image -> modal opens (FOUND-04 state-driven modal works) |
| `/3d-printing` | Print styles grid renders; Materials section filtered to print services |
| `/3d-printing/<any-slug>` | Single-style page renders |
| `/about` | About page renders with profile content |
| `/contact` | Contact form renders; honeypot is visually hidden; response-time promise visible; submit a test message and confirm Netlify receives it (check Netlify Forms tab for the new submission) |
| `/quote` | Quote page renders; tabs (3D / Laser) work; drop a test STL OR SVG file -> geometry parses without console errors; pick a material + quantity -> price range updates; reCAPTCHA either loads (if env var set) OR shows "spam protection isn't loaded yet" gracefully (if env var not set) |
| `/shop` | Coming Soon page renders; submit a test email to shop-notify form; confirm Netlify Forms tab shows the submission |
| `/<any-non-existent-route>` | NotFound page renders (the SPA fallback `[[redirects]]` is what makes this work — without it Netlify would 404 instead of letting React Router handle the route) |
| `/materials` (legacy) | Redirects to `/styles#materials` (the `_redirects` 301 still wins over the new catch-all) |

5. **Open the Netlify Forms tab** for the deploy preview branch. Verify BOTH `contact-form` AND `shop-notify` appear with the same field list as production (the contact-form should have: bot-field, name, email, service, subject, message; shop-notify should have: bot-field, email).

6. **Check the browser DevTools console** on each URL above. Acceptable: no errors. Acceptable: framer-motion warnings about reduced-motion (existing). NOT acceptable: `process is not defined` (would mean Pitfall 4 needs the `define: { 'process.env': '{}' }` shim added to vite.config.js).

7. **Confirm asset hashes are present** in the Network tab — `index-<hash>.js`, `index-<hash>.css` patterns in `/assets/`. Confirm cache headers are sane (Netlify defaults are fine).

8. **If anything fails:** Document the failure, do NOT merge. The plan stays open until the owner is satisfied. Common failure modes and fixes:
   - Form submissions return 404 -> Pitfall 2 (form prerender broke); compare `build/index.html` form blocks to `public/index.html` original; restore byte-identical.
   - `process is not defined` in console -> Pitfall 4; add `define: { 'process.env': '{}' }` to vite.config.js, push, retest.
   - reCAPTCHA shows "spam protection isn't loaded yet" -> Task 1 dashboard env var rename was skipped or done wrong; revisit Task 1.
   - Sitemap missing or 404 at `/sitemap.xml` -> Pitfall 3; verify `vite.config.js#build.outDir` is `'build'` and `scripts/generate-sitemap.cjs` line 59 still hardcodes `'build'`.
